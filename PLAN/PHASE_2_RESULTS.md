# Phase 2 — Swift schema/data applier

Validated locally on 2026-09-25 with the Phase 1 pinned stack: MySQL 8.4.8 → Maxwell 1.46.0 → Pub/Sub emulator → Swift 6.2.1 → MySQL 5.7.42.

## Result

`make phase2` passed from fresh application databases in two isolated Compose projects: `maxwell-phase2-1790382025-49045` and the final run `maxwell-phase2-1790382188-50142`. Evidence remains under their matching `artifacts/` directories (ignored by Git). The final run additionally retains Chinese/emoji text in final rows and recovers pending DDL through a newly connected applier.

- 21 unique source events reconciled against the independent expected operation sequence, audit subscription and target ledger. This includes writes later overwritten or deleted, standalone index DDL, table drop/recreate and the final marker.
- Matching semantic schemas and sorted rows for all three final tables. The workload exercises composite primary keys, a primary-key update using the old key, CRUD, and an add-column immediately followed by writes.
- Exact unsigned 64-bit and DECIMAL(65,30) values, binary bytes, Unicode text/JSON, distinct SQL NULL/JSON null and microsecond datetime/timestamps converged.
- An older update republished after convergence was deduplicated without reverting newer state. The final source marker reached the applied checkpoint.
- Zero incomplete DDL journals and zero observed DLQ deliveries, including a three-second drain period.
- Target integration fault seams passed: DDL completion after an exception between implicit commit and ledger commit; DML rollback without checkpoint advancement; duplicate suppression; changed-payload identity collision rejection; unrelated schema drift rejection; and an incomplete-DDL barrier preventing later writes.
- Eight Swift unit tests passed locally and during the Linux Docker build. The Maxwell capture adapter's Java checks also run as part of its image build.

## Implementation

The applier is single-writer/serial. DML uses prepared statements and commits its mutation, ledger record and checkpoint atomically. DDL uses a durable before/after schema journal and postcondition checks; its mutation cannot share the DML transaction because of MySQL implicit commits. The consumer acknowledges only after the applier returns successfully. A source-history namespace plus binlog/row identity provides deduplication independent of Pub/Sub message IDs.

DDL is parsed with an explicit, deliberately narrow grammar. See [README](../README.md#phase-2-checks-and-contract) for the accepted forms, types, defaults and capture contract. Invalid or unsupported delivered events stop the consumer without acknowledgement. Normal retry/quarantine/DLQ handling is not implemented yet.

## Compatibility findings resolved

1. MySQL 5.7 rejects explicitly nullable columns in a table-level primary key. Reconstructed DDL explicitly marks primary-key columns NOT NULL.
2. MySQL 8.4 adds `/* generated by server */` to binlogged DROP TABLE statements. Only that exact trailing, non-executable annotation is accepted; arbitrary/executable SQL comments remain rejected.
3. Upstream Maxwell deliberately blacklists standalone CREATE/DROP INDEX. A small checked-in adapter routes these through its normal TableAlter/schema-history/publication path while preserving original SQL for Swift validation. Docker applies the adapter to checksum-pinned upstream source and tests it during the build.
4. With Maxwell `output_nulls=true`, SQL NULL and JSON null become indistinguishable. This POC uses FULL binlog row images plus `output_nulls=false`: missing fields are SQL NULL, explicit null in JSON is JSON null. The end-to-end test checks both.
5. MySQL 5.7's explicit timestamp default behavior is set on the database container, avoiding additional administrative privileges for the consumer account.

## Boundaries and next phase

The original Phase 1 stack/volumes were not reset. Disposable Phase 2 stacks and volumes were removed after preserving their diagnostic artifacts. `PLAN/POC_CONTEXT.md` and `PLAN/s1` were not changed.

This is the Phase 2 exit gate, not completion of the full POC. Phase 3 should turn this focused harness into configurable scenarios with richer per-operation manifests and negative assertion tests. Phase 4 still needs actual container/process crash tests, continuous lease renewal, retry/backoff, durable blocked/quarantine state, DLQ publication and repair/replay. Emulator restart remains queue loss. Other DDL Maxwell suppresses, such as TRUNCATE and routines, is outside the supported workload and needs a capture policy before broader use. Whole-source-transaction atomic visibility is not promised.

The optional local upstream clone is `.upstream/maxwell`, pinned to tag `v1.46.0` / commit `a338a3d9e2e2d1c616dc83470438a1996a8584c6`; both Git and Docker ignore it.
